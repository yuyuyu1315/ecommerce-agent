# 用户反馈内测记录（反馈闭环 · 模拟试用）

> **口径声明（重要）**：以下为**内测模拟数据**（邀请 2-3 位同学/朋友模拟运营决策者试用），
> 非真实生产用户数据。用于验证"建议 → 采纳/拒绝 → 归因 → 迭代"的反馈闭环机制。
> 面试表述示例："我组织了 3 人内测，用 5 个真实商品跑通反馈闭环，采纳率 60%，拒绝主因是价格敏感，据此调了定价策略。"

## 使用方法

1. 打开前端 http://localhost:5173 或后端 API（/api/agents/selection/analyze、/api/agents/pricing/analyze）；
2. 请朋友扮演"运营决策者"，对 AI 给出的选品/定价建议做决策（采纳 / 拒绝 / 修改后采纳）；
3. 把每条决策如实填入下表（**只填真实发生的内容，不要编造**）；
4. 填完后，把本表放回 docs/ 目录并 push 到 GitHub（README 自动可见）。

## 决策落库（让闭环可见）

系统已内置状态流转：`price_suggestions.status`（pending → approved / rejected），
`product_selections.status` 同理。**真实执行后**可在看板/接口中直接统计：

- 采纳率 = approved 数 / 建议总数
- 拒绝原因聚类（从记录表"拒绝原因"列归纳）
- 迭代动作（根据原因调整提示词、策略参数或知识库）

## 拒绝原因 → 迭代方向速查（示例）

| 拒绝原因（真实填写后归纳） | 对应迭代动作 |
|---|---|
| 价格过高/涨幅过大 | 调整定价策略权重（成本加成系数/竞争价格带上限） |
| 品类与店铺定位不符 | 选品 Agent 增加"店铺定位"输入参数 |
| 建议理由不充分 | 知识库补充选品/定价案例 |
| 库存风险 | 定价建议增加库存周转约束 |
